# Volibear — Agent Guide

Multi-agent engineering pipeline runtime. **Agents think. Volibear orchestrates.**

## Critical: Build Order

The CLI (`dist/index.js`) is a single bundled file — it does NOT exist until built.

```bash
# Full verification (must pass in this order for CI):
pnpm install --frozen-lockfile
pnpm exec tsc -b
pnpm bundle          # generates dist/index.js + resources/
pnpm test            # tests need dist/index.js for build.test.ts
```

**Never run `pnpm test` without first running `pnpm bundle`.** The `build.test.ts` suite spawns `node dist/index.js` and will fail with MODULE_NOT_FOUND.

## Workspace Structure

```
packages/
  contracts/   @volibear/contracts  — Zod schemas (stages, pipelines, gates, executors, runs)
  core/        @volibear/core       — Config loader, JSONL event log, artifact store, run state
  runtime/     @volibear/runtime    — Pipeline parser, RubberduckSession, RunOrchestrator, gates
  executors/   @volibear/executors  — CLI adapters (opencode, codex, claude, mock)
  cli/         volibear-cli         — Terminal entry point, install wizard, commands
```

Entry point chain: `packages/cli/src/index.ts` → commands → runtime → core → contracts.

## Key Commands

| Command | What it does |
|---------|--------------|
| `pnpm bundle` | esbuild bundle → `dist/index.js` + copies `resources/` |
| `pnpm smoke` | Pack tarball, install in temp project, run through npx end-to-end |
| `pnpm test` | Vitest — runs all `packages/**/src/**/*.test.ts` |
| `pnpm lint` | ESLint on `packages/*/src` |

## Testing Quirks

- `vitest.config.ts` aliases `@volibear/*` to source files (not dist), so unit tests run against sources.
- `build.test.ts` is the exception: it spawns the **bundled** `dist/index.js` via `execFileSync`. This is why `pnpm bundle` must precede `pnpm test`.
- Tests use `globals: true` from vitest config — `describe`, `it`, `expect`, `vi` are available without imports (but imports also work).

## Executor / CLI Integration

Executors spawn coding CLIs (opencode, codex, claude) as child processes.

- **Prompt goes via stdin**, not CLI argument. This prevents TUI-based CLIs from hanging.
- Stdout may contain ANSI escape codes, markdown fences, and TUI headers — `parseJson()` strips these before extracting JSON.
- Agent instructions come from `agents/*.md` files, resolved in order: `.volibear/agents/` → `~/.volibear/agents/` → bundled `resources/agents/`.

## Release Flow

Tag-driven publish via GitHub Actions using npm trusted publishing (OIDC, no NPM_TOKEN).

```bash
npm version patch -m "%s" && git push --follow-tags
```

The tag triggers `release.yml`: verify (tsc + bundle + test + smoke) → publish → confirm.
The confirmation step retries 5x with 10s delays for npm propagation delay.

## Gotchas

- `dist/` and `resources/` are gitignored — they are build artifacts generated by `pnpm bundle`.
- `.volibear/.runs/` contains pipeline state — gitignored.
- The npm package name is `volibearq`, not `volibear`. Use `npx volibearq` (not `npx volibear`).
- Both binaries (`volibearq` and `volibear`) point to the same `dist/index.js`.
- `pnpm-workspace.yaml` only includes `packages/*` — `.opencode/` has its own separate `package.json` with `@opencode-ai/plugin`.
